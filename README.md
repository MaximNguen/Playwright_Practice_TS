# Playwright UI Autotests — People Help System

Портфолио-проект: фреймворк UI-автотестов на **Playwright + TypeScript** для SaaS-платформы управления офисом (задачи, отделы, сотрудники, материалы, администрирование, ИИ-чат).

> Тестируемый продукт коммерческий и недоступен публично. В репозитории — полностью готовый тестовый фреймворк; тесты запускаются против локального или внутреннего стенда. Скриншоты прогонов и отчётов добавляются отдельно.

## Стек

- **Playwright Test** 1.65 + **TypeScript** 5.9 (strict mode)
- **Page Object Model** + кастомные фикстуры Playwright
- **Allure Report 3** и встроенный HTML-отчёт Playwright
- **dotenv** — конфигурация через переменные окружения
- Скриншоты, видео и trace при падениях, retries в CI

## Что покрыто

| Область | Проверки |

| Аутентификация | вход для admin / manager / employee, неверные данные, валидация полей, восстановление пароля, регистрация, выход |
| Задачи | создание с исполнителем и вложением, валидация, смена статуса, отмена диалога, удаление |
| Профиль и настройки | обновление профиля, переключение вкладок |
| Отделы | создание, карточка отдела, редактирование |
| Сотрудники | создание, валидация пароля, редактирование и удаление |
| Материалы и диск | загрузка файла, предпросмотр, создание папки |
| Администрирование | вкладки, создание офиса и программы |
| Чат | создание беседы, переключение роли ассистента |
| Дашборд | переключение вида графика |
| Навигация | все разделы, боковое меню, неизвестный маршрут |
| Права доступа | запрет админ-раздела и управляющих действий для сотрудника |
| E2E | сквозные сценарии: профиль → выход, задача → выполнение → удаление, материал → предпросмотр, отдел, CRUD сотрудника |
| Негативные | невалидный вход и регистрация, пустая задача, короткий пароль, отмена диалога |

## Структура

```text
.
├── playwright.config.ts        # конфигурация Playwright, отчёты, retries, trace
├── tsconfig.json               # strict TypeScript + alias @/*
├── test-data/                  # файл для проверки загрузки
├── src/
│   ├── config/env.ts           # BASE_URL и пароль демо-пользователей
│   ├── data/                   # пользователи, маршруты, тестовые данные
│   ├── fixtures/test.ts        # кастомный test: page objects, upload-файл, Allure
│   ├── pages/
│   │   ├── BasePage.ts         # общие действия и ожидания
│   │   ├── LoginPage.ts        # страница входа и регистрации
│   │   └── AppPage.ts          # навигация и действия внутри приложения
│   └── utils/                  # логин с ретраями, уникальные данные, файлы
└── tests/
    ├── functional/             # функциональные UI-тесты
    ├── navigation/             # маршруты, меню, сетевые проверки
    ├── e2e/                    # сквозные сценарии (@e2e)
    └── negative/               # негативные проверки и права (@negative)
```

## Быстрый старт

Требования: Node.js 20+, запущенное приложение по адресу из `UI_BASE_URL`.

```bash
npm install
npx playwright install chromium
```

Создайте `.env` на основе `.env.example`:

```bash
# macOS / Linux
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env
```

Запуск тестов:

```bash
npm test
```

## Отчёты и диагностика

- **Playwright HTML** — папка `playwright-report/`, команда `npm run report`.
- **Allure** — результаты в `allure-results/`, просмотр через `npm run allure:serve`. Каждый шаг Page Object размечен `allure.step`, тесты — `feature` / `story` / `severity`.
- При падении автоматически сохраняются скриншот, видео и trace (`test-results/`).
- В CI включены 2 ретрая; локально — без ретраев, чтобы видеть нестабильность.

## Принципы

- **Page Object Model**: селекторы и действия инкапсулированы в `src/pages`, тесты читаются как сценарии.
- **Фикстуры вместо дублирования**: `page`, page objects и уникальный файл для загрузки выдаются через `src/fixtures/test.ts`.
- **Изоляция данных**: email и названия генерируются с UUID, чтобы прогоны не конфликтовали.
- **Явные ожидания**: `expect` и `waitFor` вместо фиксированных пауз.
- **Конфигурация снаружи**: адрес стенда и пароль задаются переменными окружения, секреты не хранятся в репозитории.
- **Единый вход**: `loginAs()` с ретраями используется всеми сценариями.

## Скриншоты

Скриншоты отчётов и результатов прогона будут добавлены в репозиторий после запуска на закрытом стенде.
